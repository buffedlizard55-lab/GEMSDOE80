## Why H33-2-B2 scored high (0.2778, user-cited; NOT organizer-confirmed in this checkout)
DTI is a covering budget: each truth pixel earns only the **max** kernel-weighted prediction within 300 m (3 px), while every positive pixel pays FP cost alpha=0.2 weighted by (1 - kernel credit). A thick surface wastes mass re-covering the same truth; sparse unit dots off the catalogue concentrate credit. Break-even for a marginal dot is roughly credit > alpha x DTI (~0.052 at DTI 0.26). H33-2-B2 deleted all dots within 2 px of the catalogue (37,654 dots, 0 on-catalogue, all-finite zeros encoding) — exactly the geometry that raises credit per pixel. GEMSDOE32 itself labelled it UNSCORED / projected 0.2747, so 0.2778 is owner/user-reported, not a receipt (sources.md §C).

## Can a unique file beat 0.2778?
In principle yes: the official public leaderboard (re-read 2026-10-22) has #1 xiaofanhu **0.4413**, #2 0.3904 — higher scores demonstrably exist. But H80-C's HOLDOUT-DTI **0.0507** is a catalogue hide-and-recover proxy; by construction it cannot reward a genuinely new off-catalogue fault, so it neither predicts nor excludes a live score above 0.2778. Copying H33's dots would violate the lane protocol (Spearman > 0.90 / >70% dots within 3 px = duplicate). The only honest path is a different detector (H80-C is one; H80-F/G/H are next, unrun) plus an organizer receipt. **No projection is written as a score.**
